      How the balance is worked out
      • The explorer's balance is the balance at the last signed checkpoint, which can be hours old. Transfers after it aren't in that number yet.
      • This page reads the address history, checks each transaction with /api/explorer/tx/<id>, and adds the ones the checkpoint doesn't cover yet: final incoming in, final and pending outgoing out.
      • Final means 5 or more peer attestations, or covered by a 5/5-signed, chain-anchored checkpoint. Pending is on the ledger but not final yet. Included means the node accepted it into a block and it's waiting for attestations. Not found means the node has never seen that txid.
      • Mining rewards credited after the checkpoint, and reward vesting, aren't in the public history, so a mining account can hold slightly more than shown and may not be able to send unvested rewards yet. The only definitive "can I send this?" check is a signed dry run with your own client (node poa.mjs send … --dry or POST /api/submit?dry=1). This page never asks for a key, so it can't do that.
      • Updates every 15 seconds while this tab is visible. Requests go only to https://minepoa.com, enforced by this page's Content-Security-Policy. Nothing is stored.
